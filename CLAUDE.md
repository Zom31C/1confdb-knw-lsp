# CLAUDE.md — написание кода 1С с опорой на базу знаний 1confdb-knw-lsp

Этот дистрибутив содержит экстрактор конфигураций 1С:Предприятие 8 в SQLite и
MCP-сервер **1confdb-knw** — read-only базу знаний по конкретной конфигурации:
объекты метаданных, реквизиты с типами, табличные части, модули кода (BSL),
запросы СКД. Дополнительно сервер поднимает **BSL Language Server** (дочерний
процесс) и отдаёт его инструменты с префиксом `bsl_` — AST-анализ кода
конфигурации: символы, ссылки, переходы, типы, диагностики. Сервер НЕ изменяет
конфигурацию — он справочный; код и запросы ты пишешь сам, а из базы и
анализатора берёшь факты: имена объектов, полей, методы-примеры, связи.

**Глоссарий 1С, схему БД, формат путей объектов, правила вызова общих модулей,
мульти-базовость (`db`, `db='*'`, `db_open`/`db_use`), сравнение баз
(`compare_object`, `extension_diff`, `configuration_info`), группы измерений/ресурсов/
реквизитов регистров, основы языка запросов и рекомендованный порядок работы
инструментами confdb сервер выдаёт сам** — в `initialize.instructions` (PRIMER),
при подключении. Этот файл их не повторяет. Здесь только то, чего в PRIMER нет:
как подключить сервер, рабочий процесс анализа кода инструментами `bsl_*`, минимум
языка BSL для генерации кода, полный список конструкций языка запросов и правила
стиля.

## Подключение к серверу

- stdio: `1confdb-knw.bat <база.sqlite> [--lsp-workspace <каталог-дампа>]`
  (или `python -m confdb.mcp_server <база>`);
- сеть: `1confdb-knw.bat <база> --port 8765`, клиент — `{"url": "http://127.0.0.1:8765/mcp"}`;
  с другой машины — через туннель `ssh -L 8765:127.0.0.1:8765 user@host`.

С `--lsp-workspace` (каталог дампа от `confdb extract --dump`, подготовленный
`confdb prep-lsp`) доступны инструменты `bsl_*`; workspace запоминается в
конфиге, при следующих запусках опцию можно не указывать. Без jar/java сервер
работает в обычном режиме (без `bsl_*`). Инструменты `bsl_*` доступны в обоих
транспортах — и в stdio, и по HTTP (`/mcp`, в т.ч. через SSH-туннель), как и
инструменты confdb: шлюз работает на уровне сервера, транспорт прозрачен.

Если сервер не поднят, попроси пользователя запустить его (confdb-ui.bat, пункт 1)
или запусти сам одной из команд выше.

## Рабочий процесс — метаданные (инструменты confdb)

Ошибки инструментов возвращаются с кодом категории (`BAD_ARGS`, `BAD_REQUEST`,
`DB_LOCKED`, `DB_SCHEMA`, `DB_ERROR`, `IO_ERROR`, `INTERNAL`); `DB_LOCKED`
транзитна — вызов можно повторить.

## Рабочий процесс — анализ кода (инструменты bsl_*)

Файлы задаются путями относительно корня дампа, например
`Catalog/Товары/Товары.obj.bsl`. Модуль объекта = `<Имя>.obj.bsl`, менеджера =
`<Имя>.mgr.bsl`; общий модуль — `CommonModule/<Имя>/CommonModule.obj.bsl`.

1. `bsl_document_symbols` — структура модуля: области, процедуры, функции
   (быстрее и точнее, чем читать файл целиком). Для больших модулей вызывай
   с `outline: true` — вернёт компактное текстовое оглавление (области и
   сигнатуры с номерами строк) вместо полного JSON-дерева.
2. `bsl_hover` / `bsl_type_at_position` — тип и описание символа в позиции
   (строка/колонка с нуля): что вернёт вызов, какого типа переменная.
3. `bsl_definition` — переход к определению символа.
4. `bsl_find_references` — кто использует метод/переменную (impact analysis кода).
5. `bsl_call_hierarchy` — граф вызовов процедуры/функции (вверх и вниз).
6. `bsl_global_member_info` / `bsl_global_member_search` — глобальные методы
   и объекты платформы (Сообщить, Справочники, …) по имени/категории.
7. `bsl_type_info` — карточка типа платформы или конфигурации.
8. `bsl_analyze_file` — полный разбор файла: диагностики (включая ошибки
   запросов из `confdb check-queries`) и метрики.

Связка двух источников: метаданные (что есть в конфигурации) бери у confdb,
поведение кода (кто кого вызывает, типы выражений) — у `bsl_*`. Первый вызов
`bsl_*` сразу после старта сервера может попасть на индексацию дампа
(~10–30 с) и вернуть пустой результат — повтори вызов.

Поиск по вызовам: кто вызывает метод ПО ВСЕЙ конфигурации — `find_methods`
(маска = имя метода, ищет по всем модулям); `bsl_find_references` и
`bsl_call_hierarchy` разрешают ссылки в проиндексированном workspace —
указывай позицию ОБЪЯВЛЕНИЯ метода, причём курсор должен стоять НА ИМЕНИ
метода (на идентификаторе), а не в начале строки; на вызовах встроенных
методов платформы (Записать, Сообщить, …) они возвращают пустой результат,
а не ошибку. Не уходи в `sql`-перебор `LIKE` ради поиска вызовов —
`find_methods` быстрее и полнее. Файлы дампа НЕ лежат в твоем рабочем
каталоге — не ищи их на диске (Read/Glob), весь анализ только через
инструменты `bsl_*`.

## Язык 1С (BSL) — минимум для генерации кода

Ключевые слова русские. Каркас:

```bsl
// директивы контекста (важно: клиент и сервер — разные среды выполнения)
&НаСервере
Функция МояФункция(Параметр) Экспорт
    Перем Локальная;
    Если Условие Тогда
        // …
    ИначеЕсли Другое Тогда
        // …
    Иначе
        // …
    КонецЕсли;
    Для Каждого Строка Из Коллекция Цикл
        // …
    КонецЦикла;
    Возврат Значение;
КонецФункции

&НаКлиенте
Процедура КомандаНаКлиенте(Команда)
    // …
КонецПроцедуры
```

- Литералы: `"строка"`, `123.45`, `'20260101'` (дата), `Истина` / `Ложь`, `NULL`,
  `Неопределено`. Операторы: `=`, `<>`, `<`, `>`, `<=`, `>=`, `+ - * /`, `%`,
  `И`, `ИЛИ`, `НЕ`, скобки. Строки соединяются `+`.
- Обращение к данным: `Объект.Реквизит` (в модуле объекта),
  `Справочники.Имя`, `Документы.Имя`, `РегистрыСведений.Имя`,
  `РегистрыНакопления.Имя` — менеджеры; `Объект.Ссылка` — ссылка записи;
  табличная часть: `Объект.ИмяЧасти.Добавить()`, обход `Для Каждых Строк Из Объект.ИмяЧасти`.
- Модули в базе знаний: `code_name` = `obj` (модуль объекта), `mgr` (модуль
  менеджера), модули форм и общих модулей; у общих модулей `context`
  (Сервер / Клиент / Вызов сервера …) — учитывай контекст при заимствовании кода.
- Синонимы и имена бери ТОЛЬКО из `object_card` / `find_field` — не выдумывай.

## Язык запросов 1С — конструкции, которые обязан принимать `check_query`

PRIMER даёт имена таблиц, виртуальные таблицы и базовый пример. Полный список
конструкций (проверен на 375 запросах СКД реальной конфигурации):

- `ПОМЕСТИТЬ` / `УНИЧТОЖИТЬ`, `ОБЪЕДИНИТЬ [ВСЕ]`, `СОЕДИНЕНИЕ … ПО`
  (ЛЕВОЕ / ВНУТРЕННЕЕ), вложенные запросы, `ВЫБОР … КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ`,
  `ВЫРАЗИТЬ(… КАК …)`, параметры `&Имя`, необязательные области СКД `{ … }`;
- группировка — только `СГРУППИРОВАТЬ ПО` (формы «СГРУППИРОВАНО» в языке запросов 1С
  НЕТ), в т.ч. `СГРУППИРОВАТЬ ПО ГРУППИРУЮЩИМ НАБОРАМ ((…), (…))`;
- `В ИЕРАРХИИ (…)`; `УПОРЯДОЧИТЬ ПО … ИЕРАРХИЯ [УБЫВ]`; `АВТОУПОРЯДОЧИВАНИЕ`;
- `ИТОГИ [поля] ПО [ОБЩИЕ] <точки>` с `[ТОЛЬКО] ИЕРАРХИЯ` и `ПЕРИОДАМИ(ГОД, …)`;
- псевдонимы полей и источников — с `КАК` или без него;
- поля табличной части — `Т.Часть.Поле`;
- разыменование ссылок точками работает только по конкретным типам реквизита
  (`type_str`); для составных типов соединяйся через известные цели
  (`attribute_ref` / `refs_of`).

Написал запрос → прогнал `check_query` → только потом отдавай пользователю.

## Правила

- Имена объектов/полей/методов — только из базы знаний, строго как в ней.
- Сначала ищи готовый код (`find_methods`, `skd_of`) — переиспользуй стиль и логику
  ЭТОЙ конфигурации, а не пиши «в вакууме».
- Поиск отдаёт одну страницу: `limit` (1..200) и `offset`, а последняя строка ответа
  называет общее число совпадений и `offset` следующей порции. Нужны остальные —
  листай тем же поиском, а не раздувай `limit` и не сужай маску наугад.
- Синтаксис текстов модулей этот сервер ПРОВЕРЯЕТ: BSL Language Server отдаёт
  диагностики через `bsl_analyze_file` (полный разбор файла), структуру и типы
  символов — `bsl_document_symbols`, `bsl_hover` / `bsl_type_at_position`. Написал
  модуль — прогони диагностику до того, как отдавать код пользователю; `bsl_*`
  требуют запущенного workspace (см. «Подключение к серверу»).
- Учитывай директивы `&НаКлиенте` / `&НаСервере`: клиентский код не может читать
  базу напрямую, серверный — не работает с формами.
- Результат — текст кода/запроса в ответе пользователю.
- Не уверен в точном имени метода — в `find_methods` давай частичную маску
  (кусок имени, например 'Состояние' или 'Отмен'), а не выдуманное полное имя;
  нет результата — сократи маску. Перебор `get_method` с угаданными именами
  запрещён.
- Ответы держи компактными (ориентир — до ~1200 слов): слишком длинные ответы
  обрываются лимитом токенов клиента, и вся работа теряется.
