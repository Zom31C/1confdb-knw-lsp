# QWEN.md — контекст проекта 1c-conf-db-extractor (confdb)

## Обзор проекта

`confdb` — экстрактор конфигураций 1С:Предприятие 8 (`.cf` / `.cfe` / `.epf`) в базу SQLite,
работающий без технологической платформы 1С. Назначение — получить метаданные конфигурации
в реляционной базе для генерации кода 1С (LLM/RAG, скрипты).

Алгоритм распаковки портирован из [v8unpack](https://github.com/saby-integration/v8unpack)
(лицензия MIT, см. `NOTICE.md`; оригинал для сверки лежит в `_vendor/v8unpack`).
Портируется ТОЛЬКО распаковка/разбор (decode). Обратная сборка (encode/pack/write) не нужна:
все методы `encode*` / `write_encode*` / `write_old*` удалены из кода — новые не добавлять.

Технологии: Python >= 3.9, **только стандартная библиотека** (без внешних зависимостей в рантайме;
pytest — только в dev-extras). Windows-ориентированный проект (bat-обёртки, venv в `.venv`).

## Структура репозитория

- `src/confdb/extract.py` — конвейер стадий 0/1/3 (внешние контейнеры → inflate+вложенные
  контейнеры → декодирование метаданных в дерево файлов)
- `src/confdb/__main__.py` — CLI: `extract <файл> --db … --dump … [опции]`,
  `check <база>` (проверка запросов СКД), `1confdb-knw <база> [--port N]` (MCP)
- `src/confdb/tui.py` — текстовый консольный интерфейс: меню с обновлением экрана
  (извлечение, запросы к БД, проверка СКД, запуск MCP-сервера, опции); недавние пути
  и опции — в ~/.confdb/config.json. Пользователь сознательно выбрал консольный UI
  вместо графического — не предлагать tkinter/GUI
- `src/confdb/db/writer.py` — запись дампа стадии 3 в SQLite (таблицы `source`, `meta_object`
  с `parent_id`+`ord` для обхода дерева «как в конфигураторе», `module` с `context` для общих
  модулей, `method` — модули, разбитые на процедуры/функции с директивами `&НаКлиенте`/`&НаСервере`
  (парсер `src/confdb/bsl_parser.py`), `subsystem_content`, `file`)
- `src/confdb/v8/` — ядро порта: `container.py`, `container_reader.py`, `container_doc.py`,
  `decoder.py`, `helper.py` (скобкофайлы `{}`), `json_container_decoder.py`, `metadata_types.py`,
  `meta_object.py` (корневые объекты); `MetaDataObject/` укрупнён: `objects.py` (~90 классов
  метаданных), `core.py`, `form.py` (парсеры форм 5.x/9.x), `form_elements4/26/27.py`;
  классы выбираются по имени реестром `helper.get_class_metadata_object`
- `tests/` — юнит-тесты на синтетических фикстурах (writer, CLI, парсер скобкофайлов)
- `_vendor/v8unpack/` — исходник-эталон (MIT) для сверки семантики; не модифицировать
- `_tmp/` — рабочие/сравнительные скрипты (`compare_decoders.py`, `compare_dumps.py`,
  `check_db.py`); игнорируется git'ом
- `SmallBusinessKz_3_0_4_4_cf.cf` — тестовый файл 885 МБ («УправлениеНебольшойФирмойДляКазахстана»);
  пользователь перемещает его между корнем репозитория и `cf\` развёрнутой копии
  `D:\Projects\1confdb-knw-main` (в git не входит, `*.cf` в .gitignore);
  используется для end-to-end проверок
- `.venv/` — venv проекта; **не удалять**
- `qwen-code-export-*.md/.json` — экспорты прошлых сессий (история договорённостей)

## Команды (Windows, из корня проекта)

```bat
:: установка (один раз)
.venv\Scripts\python.exe -m pip install -e ".[dev]"

:: тесты
test.bat                      :: = .venv\Scripts\python.exe -m pytest

:: CLI
confdb.bat extract config.cf --db out.db --dump out_tree

:: консольный интерфейс
confdb-ui.bat                 :: = .venv\Scripts\python.exe -m confdb.tui

:: проверка запросов СКД (на тестовой конфигурации 375/375)
confdb.bat check out.db

:: MCP-сервер: stdio по умолчанию; --port — HTTP для SSH-туннеля
1confdb-knw.bat out.db --port 8765

:: статическая проверка
.venv\Scripts\python.exe -m compileall -q src\confdb\v8
```

Полный end-to-end прогон тестового `.cf` занимает ~3 минуты с `--workers 8` —
в обычные тесты не включать.

## Архитектурные факты и подводные камни

- Конвейер повторяет v8unpack: стадия 0 (чтение внешних V8-контейнеров 32/64-бит),
  стадия 1 (raw-deflate inflate + рекурсивные вложенные контейнеры), стадия 3
  (скобкофайлы `{}` → JSON, модули → `.bsl`). Нумерация стадий — как в v8unpack (0/1/3).
- Формат скобкофайлов построчный: вложенный объект начинается с `{` в начале строки; значения
  не начинаются с начала строки; пробелов после запятых в реальном формате нет.
- `json_container_decoder.decode_object` оптимизирован: значения добавляются срезом
  (регекс `_RUN_PARAM` + `str.find`), а не посимвольно. Исходный посимвольный вариант квадратичен
  и на скобкофайлах форм 50–80 МБ (регламентированные отчёты) тормозит на порядки.
  При правках парсера сохранять эквивалентность оригиналу (сверка: `_tmp/compare_decoders.py`
  против `_vendor`, `_tmp/compare_dumps.py` для дампов).
- Каталог подобъектов в дампе и БД называется по имени класса (`CatalogForm`), а не `Form`.
- Кодировки: скобкофайлы читаются `utf-8-sig`, при ошибке — `windows-1251` (helper.brace_file_read).
- Временные каталоги стадий 0–1 создаются в temp ОС (`tempfile.mkdtemp('confdb_')`) и удаляются
  в `finally` (кроме `--keep-temp`).
- venv создан из MS Store Python: запущенный `.venv\Scripts\python.exe` — лаунчер, реальный
  рабочий процесс — дочерний `python3.10.exe` (CPU/память смотреть у него).
- В окружении машины **нет git** (`git` не в PATH) — команды git недоступны.

## Соглашения разработки

- Комментарии, docstring, сообщения пользователю — на русском языке.
- Никаких внешних зависимостей в рантайме; новый функционал — только stdlib.
- Не добавлять encode/запись формата; не трогать decode-логику без сверки с `_vendor/v8unpack`.
- Тесты — на малых синтетических фикстурах в `tests/` (быстрые); тяжёлые end-to-end проверки
  на 885-МБ файле запускать вручную/в фоне.
- `.gitignore`: `_tmp/`, `_out/`, `*.db`, `*.sqlite`, `.venv/`, тестовый `*.cf` — не коммитить
  большие артефакты; тестовый `.cf` и `.venv` на диске сохранять.
- Точки входа регистрировать в `pyproject.toml` (`[project.scripts]`), bat-обёртки в корне —
  в стиле `confdb.bat` (`"%~dp0.venv\Scripts\python.exe" -m …`).
